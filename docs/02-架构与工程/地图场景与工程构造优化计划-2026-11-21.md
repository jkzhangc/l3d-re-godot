# 地图场景与工程构造优化计划

版本：0.3｜日期：2026-11-21｜状态：用户已扩大授权至常驻会话、公共界面与既有地图迁移；实现完成，最终验收及提交状态见第十一节。

适用范围：Godot `4.6.3.stable.official.7d41c59c4`，Windows Desktop。冻结清单 `docs/design-freeze.json` 为 v4。GameSession 为引擎当前场景，MapLocator 提供活动源地图身份；保留原存档地图键、机关相对路径、逐图 NetworkWorld 与 Host 权威协议。

第八节保留文档整理、第十节保留首批兼容改造的历史状态。原方案的待确认项和第十节“尚未实施”不代表当前仍未完成；当前结构、验收和剩余限制以第十一节为准。

## 一、结论与需求收敛

**先明确地图、角色生成和公共界面的责任，再统一装配与生命周期；最后才考虑常驻游戏主场景。目录整理可以先做，但不能代替架构调整。**

本计划按用户更正使用“地图场景构造”，不是地图插件开发。截图左侧为对方，右侧为用户；对方建议作为评审输入，不等于用户已经确认实施。聊天讨论按主题归纳，不提供未经逐字复核的引语。

| 已明确 | 本计划采用的假设 | 待确认及影响 |
|---|---|---|
| 优化地图场景构造和工程组织 | 保持现有玩法、绘图效果、存档语义与 Host 权威机制 | Q1：是否认可最终引入 GameSession 常驻战斗外壳；影响后期场景切换方式 |
| 先将散落 Markdown 分类收进一个目录 | 根目录保留四个简短发现入口；插件与独立工具自带文档原位维护 | 已按此执行；正文均以 docs/ 为新增归属 |
| 结合聊天与真实工程，而非套用空项目模板 | 先试点开头安全屋和学校内部，再覆盖战役地图 | Q2：地图能否继续在编辑器单独运行；默认保留一键调试能力 |
| 当前请求是计划，文档整理单独授权执行 | 不改主场景、Autoload、网络传输、地图节点及资源路径 | Q3：是否批准 P0/P1 工程实现；未批准前不迁移游戏代码 |

### 对聊天建议的取舍

| 讨论主题 | 本计划判断 | 具体取舍 |
|---|---|---|
| 地图不应负责整个游戏的装配 | 采纳方向 | 地图负责地形、点位、机关、环境和配置；公共 UI、玩家生成由上层装配 |
| 玩家、敌人、HUD 应与地图职责分清 | 采纳，但不等于全部搬成兄弟节点 | HUD 脱离地图；活体的渲染父节点仍需共享 Y 排序域 |
| Main 统一组织游戏 | 作为后期目标，不直接改现有 main.tscn | 当前入口是标题场景，现有 Main 不是生产基类 |
| 提示跟随视口、适配更清楚 | 先实测再定问题 | ActionHints 已有右下锚点；不能凭截图断言没有适配 |
| 工程不要依靠散落文件和隐式命名寻找功能 | 采纳 | 文档先集中；代码按职责渐进归属，不做整仓搬家 |

## 三、目标职责和场景清单

| 场景或对象（拟定） | 单一职责 | 根类型 | 谁创建/持有 | 输入 | 输出/生命周期 |
|---|---|---|---|---|---|
| GameSession | 组装一次战斗会话 | Node | 标题/读档/联机启动入口 | 会话参数 | 地图切换与退出；后期引入 |
| MapRoot / MapContext | 提供当前地图的内容和公开契约 | Node2D | 当前场景加载器，后期 MapHost | 地图配置、入口标记 | 容器、边界、配置引用；逐图 |
| Player / Enemy / Pickup | 承载实体行为与表现 | 沿用现有根类型 | 现有单机或 Host 生成流程 | 状态、资源 ID、位置 | 状态/表现；实体逐图、数据跨图 |
| GameplayUI | 承载本端战斗界面 | Node + 现有 CanvasLayer 子场景 | 公共装配器 | 本机状态和模式 | HUD、菜单、总结展示；不结算伤害 |
| CameraRig | 管理本端镜头绑定和边界 | Node2D | 公共装配器 | 本机实体、地图边界 | 视口表现；不拥有玩家数据 |
| SessionBootstrap | 协调地图装配阶段 | Node | 当前 GameInit 门面，后期 GameSession | MapContext、运行模式 | 阶段完成/失败；不重写玩法 |
| NetworkWorld | 逐图 Host 权威模拟与镜像装配 | 沿用现有 Node | 原 GameInit 路径 | Net 与地图引用 | 保留原 RPC 宿主和逐图清理语义 |

### 最终目标节点树（示意，尚未创建）

```text
GameSession (Node)
├── MapHost (Node2D)
│   └── ActiveMap (Node2D / MapContext)
│       ├── GroundLayer
│       ├── DecorLayer (Node2D, y_sort_enabled=true)
│       │   ├── 需要排序的地图物件
│       │   ├── Player*
│       │   ├── Enemy*
│       │   └── 需要排序的拾取物*
│       ├── UpperLayer
│       ├── Anchors (Marker2D / ArrivalPoint / SpawnPoint)
│       ├── Events（纯触发与流程；需排序的视觉部分不硬搬到这里）
│       └── Environment（逐图灯光、环境配置）
├── CameraRig
├── GameplayUI（组合现有 HUD/Menu 等子场景）
├── SessionBootstrap
└── NetworkWorld*（逐图重建；宿主迁移必须最后统一完成）
```

`*` 为运行时创建。这里分离的是“谁负责创建与结算”，不是为了整齐把所有实体放到独立 Entities 容器。角色与物件仍须处于经过验证的同一排序域；不插入未参与 Y 排序的 Players/Enemies 中间容器。现有 Decor 既可能是 TileMapLayer，也可能是 Node2D，先兼容后归一化。

地图不存预置活体玩家和重复 HUD；出生点是标记，不是玩家父节点。跨图保留 Players/Net 的状态，不把同一玩家节点强行跨图搬来搬去。地图被释放时，逐图实体随之清理。尸体、上层图块、夜间灯光和屏幕提示维持既有已验证的层级语义。

### 关键契约（拟新增，名称待实施前确认）

- MapContext 显式提供 `map_id`、源场景路径、地图类别/安全屋标记、角色排序容器、地面与相机边界层、到达点与 DirectorConfig。旧地图先通过适配器获得这些引用，不立即加父节点或改节点名。
- MapLocator 对外统一“当前地图”查询；迁移期间先返回当前地图本身，未来返回 MapHost 下 ActiveMap。先替换使用点，后切换实现，避免 `current_scene` 突然不再等于地图。
- 地图位置身份：对外使用源地图路径和稳定 map_id；入口沿用 arrival_id。旧存档及随机拾取路径键需要旧键读取/映射方案，未验证前不修改现有节点路径。
- 本地实体只由一条流程注册；到达点和存档应用不被默认出生位覆盖。镜头和 HUD 只绑定本端实体，不能默认绑定座位 0 或第一个 player。

### 地图进入与退出顺序

目标阶段：验证地图身份 → 加载内容 → 缓存层/点位/配置引用 → 应用运行模式 → 保持单机与联机原分流 → 建立实体/到达状态 → 绑定本端 UI 与相机 → 原有 ready 门控确认后结束加载。这个顺序是待验证设计，不是机械改排场景子节点顺序。

退出阶段：禁止旧场景新请求 → 走原有联机切图协议 → 解除逐图订阅、镜头和缓存引用 → 按原规则写回状态 → 释放逐图内容。普通图不重置导演 pacing；安全屋与离局仍走既有收尾；返回标题继续只走 `Global.go_to_title_screen()`。

## 六、工程组织：先职责后搬目录

## 七、验收矩阵和兼容红线

| 验收面 | 必测内容 | 通过条件 |
|---|---|---|
| 单机 | 新开局、切角色、存档/读档、死亡/团灭、安全屋 | 落点只应用一次、状态不串、旧档读取正常 |
| 联机 | Host/Client 双向切图、慢 Host ready、客户端先到、退出重进 | 不重复生成；无旧图 RPC、无额外连接等待；本地预测不被错误门控 |
| 地图流程 | 安全门、学校同图楼层传送、目标入口/坐标、钥匙门、防守点 | 相对 NodePath 完整；不把现有同图重载顺手改成无缝传送 |
| 地图身份 | 保存、复活、随机拾取、章节/计时、相机与触摸模式 | 不把 GameSession 路径写成地图路径；不因节点重挂重生掉落物 |
| 绘制与相机 | 玩家/敌人/地图物件上下交错、尸体、Upper、切角色、瞬移 | 遮挡与跟随不回退；无额外非排序中间容器 |
| UI | 本端/远端状态归属、HUD 数量、锚点、字体、总结与提示层 | 一个本地界面；字体统一；CanvasLayer 层号语义不变 |
| 夜图与寻路 | 现行 CanvasModulate/PointLight2D、遮挡、32×32 碰撞、地面角色 | 不恢复旧 SubViewport 光池或已移除的 path_blocked 方案 |
| 导出 | 场景清单、动态资源、UID、独立运行 | 保留 .import/.uid/.remap；编辑器运行通过不替代导出包实测 |
