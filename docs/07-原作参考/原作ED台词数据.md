## 一、表现规则

- **取谁**：只取**存活座位**的角色（队伍里还活着的角色）；多人模式沿用现有逻辑，各端只显示
  本端存活玩家操作的角色，不需要同步。
- **顺序**：按原作 ED 顺序依次展示 —— 大雄 → 胖虎 → 静香 → 圣奈 → 小夫 → 健治 → 出木杉 → 安雄 → 萨夏 → 咲夜。
- **A 批（结局感想）**：按 ED 顺序展示**所有存活角色**，每人一页。
- **B 批（登车 / 起飞 / 启动）**：与安全屋初始台词同口径，**随机挑一个存活角色**播放（一页）。
- 用**安全屋同款台词窗口**，按确定键翻页；窗口关闭后进滚动名单。
- **与安全屋初始台词的区别**：安全屋每批只显示**当前玩家角色**；ED 的 A 批会把队伍中所有存活角色依次展示。

## 三、代码与可编辑性（创意工坊预留）

数据层：`script/ed_dialogue_data.gd`；表现层：`script/director/campaign_ending.gd`。

| 层 | 内容 | 覆盖关系 |
|---|---|---|
| ① 内置默认 | `DEFAULT_A` / `DEFAULT_B` | 保底，任何情况下 ED 都能播 |
| ② 覆盖文件 | `user://ed_dialogue.json` | 玩家 / 模组可直接编辑 |
| ③ 运行时注册 | `EDData.register_campaign(campaign_id, table)` | 将来创意工坊在运行时注入 |

字段级合并：只改想改的角色 / 批次，未写的继续用内置默认。

### 覆盖文件格式（`user://ed_dialogue.json`）

```json
{
  "version": 1,
  "campaigns": {
    "assault": {
      "order": ["のび太", "ジャイアン", "静香"],
      "characters": {
        "のび太": { "a": ["结局第一行", "结局第二行"], "b": ["登车第一行"] }
      }
    }
  }
}
```

- 键 = `CharacterData.character_name`（日文名；`ジャイ` 会自动归一到 `ジャイアン`）。
- `a` = 角色结局感想，`b` = 登车 / 起飞 / 启动。
- `order` 可省略；新增角色写进 `characters` 并列入 `order` 即可参与 ED 排序。
- 改完文件后可调 `EDData.reload_override()` 立即重载，不必重启。

### 隔离规则

- 覆盖文件打不开 / 不是合法 JSON / 缺 `campaigns` → 只打 warning，整层忽略，内置默认照常。
- 单个战役格式不对 → 只跳过该战役。
- 单个角色或单批台词格式不对 → 只跳过该条，其余照常。
- 数据层不持有节点、不发信号，任何失败都不会打断 ED 流程。

## 四、提取方法（可复现）

```bash
cd tools/rm2k3_map_restore
python export_safehouse_lines.py 21 23 34    # 按角色分组打印
```

- ED 台词全部在事件 `#121` 第 1 页，命令块是 chunk `0x34`（不是 0x15 / 0x16）。
- 说话人写在正文里：`\>\C[4]大雄\C[0]` → 大雄；其后连续的 `20110` 是该角色的台词行。
- A 批 `indent=3`、B 批 `indent=4`；行尾的 `\<\|\|\|\^` 是 RM2K3 的等待/清屏控制码，导入时应剥掉。
- 编码：地图正文是 GBK / GB18030；事件名与未汉化部分是 cp932。
