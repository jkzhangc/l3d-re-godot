## 二、台词总览（按角色 × 地图）

每张安全屋的台词分**两批**（原作事件里的两段分支）：

| 批次    | 内容（按台词判断）        | 本作表现                |
| ----- | ---------------- | ------------------- |
| **A** | 刚进入安全屋的感叹 / 吐槽    | 窗口**第 1 屏** —— 该批多行**同屏显示** |
| **B** | 接着说的下一步行动 / 出发   | 按确定键翻到**第 2 屏**，再按一次关闭 |

> ★**A、B 是同一段对话的连续两屏**（2026-09-28 用户核对原作后确认），**不是两个独立时机**；
> 且**同一批内的多行同时显示**（原作对话框一次显示说话人 + 数行正文），不是一句一屏地翻页。
> 所以本作只在「进入安全屋」触发一次，两屏由窗口内部翻页完成。

```
\>\C[4]胖虎\C[0]\<          ← 整串就是一个颜色标记包裹的名字 = 说话人
这么糟糕的情况               ← 台词第 1 行（20110 续行指令）
有什么好的对策吗             ← 台词第 2 行
```

所以**不需要猜顺序** —— 每条台词天然归属到它前面的说话人行。

### 指令字节布局（LCF，BER 为**大端** 7-bit 变长）

| 指令                | 头部字节       | code  | 说明               |
| ----------------- | ---------- | ----- | ---------------- |
| ShowMessage       | `CE 7E`    | 10110 | 开一个新文本块；说话人行固定用它 |
| ShowMessage（续行）   | `81 9D 0E` | 20110 | 追加一行正文           |
| ChangeFaceGraphic | `CF 12`    | 10130 | 换脸图（说话人头像）       |

单条命令的字段顺序：`[code][indent][strlen][string][paramcnt][params...]`。

### 四个必须踩对的坑

1. **必须把 `paramcnt + params` 一起吃掉再前进**。  
   只跳过字符串会让后续锚点全部错位 —— 症状是「只扫到文件头部的一小段」。
2. **正则里 `\\>?` 是错的**：`?` 只作用于 `>`，反斜杠变成必需项 →  
   不带 `\>` 前缀的行（安全屋用的正是这种）全部匹配不上。  
   正确写法：`(?:\\>)?`。
3. **存档界面的难度 NPC 要排除**：`德田志穗` 的说明文字在**条件分支之外**（`indent=2`），  
   而安全屋台词在分支内（`indent=4`）→ 用缩进层级天然区分（脚本里是 `min_indent` 参数）。
4. **第三战役的迎接台词不在分支内**：`Map0032` 多啦A梦的迎接 / 说明在 `indent=0`  
   （条件分支之外），默认 `min_indent=3` 会漏掉。该段改为**按事件 `#147 全マップ共通処理１`  
   第 1 页的命令流**顺序提取，只保留带说话人标记的 10110/20110，不按缩进过滤；  
   存档点 NPC 属于事件 `#55 セーブ`，按事件取用即可天然排除。
