# net_proto 联机原型调试记录

更新日期：2026-08-19

## 当前结论

旧版动态 `MultiplayerSpawner` / `MultiplayerSynchronizer` 路线已从原型中移除。Godot 4.6.3 下，运行时配置的 `SceneReplicationConfig` 对 `^position` / `^hp` / `^alive` 报属性路径解析错误，Host 虽调用 spawn，但 Client 实际收不到实体和属性复制。

当前改为显式 Host-authoritative 协议：

- reliable RPC：握手、开始游戏、实体生成/销毁、首次完整世界快照
- unreliable_ordered RPC：Client 输入、Host 20 Hz 玩家/敌人状态快照
- Host 独占：玩家移动、HP、倒地/复活、敌人 AI、子弹移动和命中
- Client：上报输入、应用 Host 玩家/敌人状态，并对已可靠生成的子弹做直线视觉外推
- Client 切入游戏后向常驻 `/root/Net` 上报 `report_game_scene_ready`；Host 可暂存请求，`Game` 就绪后再消费，避免两台机器切场景速度不同时 RPC NodePath 尚不存在
- 高频状态快照不包含子弹；子弹使用 reliable spawn/despawn，首次完整快照才包含当前子弹

## 真实局域网复现问题与修复

用户在两台真实电脑上验证时，Client 已进入游戏场景，但 HUD 一直显示“等待玩家实体生成”。根因是 v2 的场景就绪请求只发送一次，而且 RPC 目标是 `/root/Game`：当 Client 加载场景快于 Host 时，Host 仍停留在 Lobby，收到的 reliable RPC 虽不会在传输层丢包，却会因为目标节点不存在而无法调用。Host 因此不知道 Client 已准备好，不会创建 Client 玩家或发送完整快照。

v3 修复：

- 协议版本：`net_proto_v3_persistent_scene_ready`。
- ready RPC 移到常驻 Autoload `/root/Net`。
- Host 的 Net 使用 `_pending_scene_ready` 暂存先到的请求。
- Host Game 启动后通过 `take_pending_scene_ready()` 消费请求。
- Client 在收到包含自身玩家的完整快照前，每 0.5 秒重试 ready。
- 自动测试给 Host 人为增加 1500 ms 场景加载延迟，强制覆盖“Client 先加载、Host 后加载”的真实竞态。

## 一致性检查

`game.gd` 与场景/实体约定：

| 项目 | 约定 |
|---|---|
| 玩家容器 | `Game/Players` |
| 敌人容器 | `Game/Enemies` |
| 子弹容器 | `Game/Bullets` |
| 玩家节点名 | `<peer_id>` |
| 敌人节点名 | `E_<enemy_id>` |
| 子弹节点名 | `B_<bullet_id>` |
| 玩家 setup | `setup(peer_id, name, pos, hp, alive)` |
| 敌人 setup | `setup(enemy_id, pos, hp, alive)` |
| 子弹 setup | `setup(bullet_id, owner_id, pos, direction)` |

玩家和敌人实体脚本只负责状态显示与绘制；子弹 `_process` 仅在 Client 侧做视觉外推。所有移动权威、命中、伤害和实体生命周期仍只有 `game.gd` 的 Host 模拟一份。

## 双进程 ENet 验证

命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File net_proto/tests/run_local_smoke.ps1
```

最终结果：

```text
[AUTO] host PASS players=2 moved=true hp_sync_source=true enemy_spawn=true bullet_spawn=true enemy_despawn=true
[AUTO] client PASS host_ok=true local_players=2 moved=true hp_synced=true enemy=true bullet=true players=2 moved=true hp_sync_source=true enemy_spawn=true bullet_spawn=true enemy_despawn=true
Timed out: False
net_proto two-process smoke test PASS
```

实际覆盖：

- Host/Client ENet 连接和协议握手
- Host 广播开始游戏与 Client `game_ready`
- 双端玩家生成
- Client 输入到 Host 权威移动
- 玩家位置和 HP 状态抵达 Client
- 敌人首次同步、生成和销毁
- 子弹可靠生成与销毁，Client 可看到子弹
- Client 断开后的 Host 玩家清理

第一次双进程测试发现高频世界快照包含过多子弹时出现：

```text
WARNING: Sending 1520 bytes unreliably which is above the MTU (1392)
```

随后将 20 Hz 快照缩减为玩家和敌人状态，子弹改由 reliable spawn/despawn 管理，Client 做视觉外推；首次可靠完整快照仍包含当前子弹。复测 Host/Client 均 PASS，且不再出现 MTU 超限警告。

Godot 会打印 `Failed to read the root certificate store`，但静态测试和双进程测试均正常完成，该 Windows 环境警告不影响当前原型。

## 后续人工验证时优先检查

1. Host 与 Client 是否都有 `[Net] HANDSHAKE_OK`。
2. Host 是否在握手后才打印 `[Net] START_GAME`。
3. Client 是否持续打印 `[Game] GAME_READY sent attempt=... via=/root/Net`；Host 是否打印 `[Net] GAME_SCENE_READY` 和 `[Game] SNAPSHOT_SENT`。
4. 两端 RPC 根路径是否都是 `/root/Game`。
5. 防火墙是否放行 UDP 27015，是否残留旧 Godot 进程占用端口。
6. 查看 `net_proto/.smoke_*_out.txt`、`net_proto/.smoke_*_err.txt` 和 `.smoke_*_godot.log`。
