## 3. 🔴 核心 bug（根因定位）

### 3.1 症状

client 诊断失败：`Entities=[]`（没有任何玩家实体）。

### 3.2 直接原因链（host err 实锤）

```
ERROR: Node '^position' not found.
   at: _get_prop_target (modules/multiplayer/multiplayer_synchronizer.cpp:41)
ERROR: Parameter "obj" is null.
   at: get_state (modules/multiplayer/multiplayer_synchronizer.cpp:164)
ERROR: Unable to retrieve spawn state.
   at: _make_spawn_packet (modules/multiplayer/scene_replication_interface.cpp:515)
ERROR: Condition "!p_buffer || p_size < 1" is true. Returning: ERR_INVALID_PARAMETER
   at: _send_raw (modules/multiplayer/scene_replication_interface.cpp:457)
```

调用点（backtrace）：`game.gd:117 _spawn_player_for` → `_ready` / `request_game_ready`；`game.gd:122 _spawn_enemy` → `_process`。

**结论**：
1. spawner 的 spawn 包在 `_make_spawn_packet` 阶段就失败 → **spawn 广播从未发到网络**（`_send_raw` 空 buffer）。
2. 每帧 `_send_sync` 同样报 `^position`/`^hp`/`^alive` not found → **属性同步也从未工作**。
3. 因此客户端 `Entities` 为空（host 端 `spawn()` 调用成功打印，但包没发出去）。

### 3.3 根因

`net_proto/script/player.gd` 与 `net_proto/script/enemy.gd` 的 `_setup_synchronizer()`：

```gdscript
var sync := MultiplayerSynchronizer.new()
sync.name = "Sync"
add_child(sync)
var cfg := SceneReplicationConfig.new()
cfg.add_property(NodePath("^position"))        # ← 这里
cfg.property_set_replication_mode(NodePath("^position"), ...)
cfg.property_set_spawn(NodePath("^position"), true)
# ^hp / ^alive 同理
sync.replication_config = cfg
```

**Godot 4.6.3 把 `NodePath("^position")` 当作普通节点路径去 `get_node_or_null` 查找，而不是「相对 root 的属性路径」，导致 `Node '^position' not found`。**（4.2/4.3 时代这是教程里的标准写法，4.6 的行为可能已变更/回归。）

### 3.4 为什么冒烟测试没抓住

`net_proto/tests/test_sync_config.gd` 只验证 `SceneReplicationConfig` 的 **get/set API**（config 存值正常），没有真正创建 synchronizer 挂树运行 → 测不出属性路径解析问题。

## 4. 待验证假设（下一步方向，按优先级）

1. **换成不带 `^` 的属性路径**：`cfg.add_property(NodePath("position"))`（相对 root 的普通属性路径）。注意：属性在 synchronizer 的**父节点**上，`root_path` 默认 `..`，普通路径 `"position"` 应该解析到父节点的属性。→ 验证是否还报 not found。
2. **确认 4.6.3 的正确写法**：查 `engine-reference/godot/` 下的 `breaking-changes.md` / `deprecated-apis.md` / `modules/networking.md`，或 Godot 官方文档 `SceneReplicationConfig` 类的 property 路径格式说明。`NodePath.get_as_property_path()` 可能与 `^` 语义相关。
3. **显式设置 root_path**：`sync.root_path = NodePath("..")`（文档默认值就是 `..`，理论上不用设，但如果动态创建时默认值为空，就需要显式设）。
4. **改用 .tscn 静态配置**：在 `player.tscn`/`enemy.tscn` 里手动放置 `MultiplayerSynchronizer` 节点 + `SceneReplicationConfig` 资源（编辑器自动生成正确的 property 路径序列化），代码里不再动态创建。这是最稳的绕行方案，但会牺牲「全代码定义」的简洁性。

> 建议先做第 1 步（5 分钟可验证）：把 `NodePath("^position")` → `NodePath("position")`，`^hp` → `hp`，`^alive` → `alive`，重跑 host 单进程测试，看 err 是否消失、spawn 包是否发出。
